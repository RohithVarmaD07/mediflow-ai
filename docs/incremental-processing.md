# Incremental correctness policy

Input identity is its content SHA-256; raw copies are immutable and checked on reuse. Canonical identity is (entity, id). A higher source_version wins even when business dates are older. Equal version/equal payload is duplicate; lower version is stale; equal version/different payload is quarantined as VERSION_CONFLICT. Within one batch, non-winning valid newer versions are superseded. No timestamp watermark excludes unseen late input.

Each input line is assigned exactly one category: invalid, duplicate, stale, superseded, accepted. Accepted winners are inserts, updates, or tombstones. Counters must sum to input lines. The complete candidate state is checked for relationships before applying changes. If winners together break referential integrity, all winners in that batch are quarantined with RELATIONSHIP_BATCH, retaining the previous consistent state. This conservative batch rejection is deliberate; quarantine can be corrected and resubmitted as a new batch.

After merge, the actual DuckDB state must equal the calculated candidate before commit. A separate test oracle rebuilds state from full valid source history using independently selected maximum versions, then checks every canonical record and analytical metric. Conflict histories are handled by explicit quarantine tests, not assumed to be order-independent. Dependencies must arrive together or parents must already exist; early orphan batches need resubmission.

The oracle now checks every intermediate snapshot, not just the final state. It independently calculates daily appointment groups, daily encounter groups, and patient summaries in Python. Before comparing metrics, it rejects duplicate output keys and requires exact equality of the expected and actual group-key sets. Missing groups, extra groups, and unexpectedly empty outputs therefore fail explicitly. Active entity identifiers are also compared as complete sets.

Regression scenarios cover completed, cancelled, and missed (no-show) appointments; cancelled-only groups with a NULL no-show rate; walk-in encounters; patients with no activity; duplicate source delivery; late date/facility corrections; and tombstones that remove entire groups. Deliberately damaged analytical results verify that the oracle rejects missing, extra, duplicate, or empty groups and incorrect measures. These checks establish the tested cases, not exhaustive correctness for arbitrary source histories.

Replays and lower versions do not alter canonical content. Analytical Parquet is regenerated from active canonical rows, which avoids stale old-date contributions. Tombstones stay in canonical storage and are excluded from published analytical views. No physical deletion of raw history occurs.
